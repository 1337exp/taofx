# taofx

Визуальный редактор эффектов и рантайм: один граф нод превращается в материал для **three.js (WebGPU/TSL или классический WebGL/GLSL)** и в фильтр **PIXI**. Слева граф, справа живой предпросмотр.

```bash
npm install
npm run dev         # редактор: http://localhost:5173 (интерфейс на @1337exp/taoui из npm, холст и редакторы на @1337exp/taoux)
npm test
npm run build:lib   # рантайм для игр: dist/
```

Репозиторий отдаёт два результата: **редактор** (приложение) и **рантайм** `@1337exp/taofx` (библиотека без Vue и редактора), которым игра показывает эффект из файла редактора.

## Эффект в вашей игре

Файл эффекта (кнопка «Сохранить» в редакторе) один и тот же, текстуры лежат внутри него. Бэкенд выбирает игра, подключая нужный вход пакета:

| Вход | Для чего | Рендерер | Что даёт |
|---|---|---|---|
| `@1337exp/taofx/tsl` | three.js | `WebGPURenderer` из `three/webgpu` (сам откатывается на WebGL2) | `createEffect(file) → { material }` |
| `@1337exp/taofx/three` | three.js | классический `WebGLRenderer` | `createGlslEffect(file) → { material }` (`ShaderMaterial`) |
| `@1337exp/taofx/pixi` | PIXI v8 | WebGL (`preference: 'webgl'`) | `createPixiEffect(file) → { filter }` |
| `@1337exp/taofx` | ядро | любой | разбор файла, граф из кода, правила связей, сборка в GLSL; не тянет ни three, ни PIXI |

```ts
// three.js, WebGPURenderer
import { createEffect } from '@1337exp/taofx/tsl';
const effect = createEffect(await (await fetch('fire.json')).text());
mesh.material = effect.material;

// three.js, классический WebGLRenderer (как в проектах на ShaderMaterial)
import { createGlslEffect } from '@1337exp/taofx/three';
const effect = createGlslEffect(text);
mesh.material = effect.material;

// PIXI (WebGL или WebGPU)
import { createPixiEffect } from '@1337exp/taofx/pixi';
const effect = createPixiEffect(text);
sprite.filters = [effect.filter];

// везде одинаково: свой отсчёт времени (пауза, перемотка) и ошибки без падения игры
renderer.setAnimationLoop((t) => effect.setTime(t / 1000));
if (effect.errors.length) console.warn(effect.errors); // граф не собрался: эффект пурпурный, игра не падает
```

- **Возможности цели.** Нода объявляет, что ей нужно: «Френель» требует нормаль поверхности (есть у 3D-меша, нет у фильтра PIXI), «Исходная картинка» требует спрайт (есть только у PIXI). Компилятор не соберёт граф для цели без нужного и скажет, какая нода мешает: `Fresnel needs normal, which the pixi target does not provide`. Лишняя неподключённая нода сборку не ломает.
- **PIXI.** Эффект рисуется внутри силуэта спрайта (непрозрачность умножается на его альфу). Цвет графа линейный, шейдер сам переводит его в sRGB: PIXI этого не делает. Фильтр содержит обе программы: GLSL для рендерера WebGL и WGSL для WebGPU, PIXI выбирает по `preference` приложения. Если у своей ноды нет WGSL-реализации (`wgsl` в `defineNode`), на WebGPU фильтр пурпурный, а причина в `effect.gpuErrors`.
- **Подключение слинкованного пакета.** В `vite.config.ts` игры `resolve.dedupe: ['three']` (и `'pixi.js'`), иначе у пакета будет своя копия. Не кладите страницы с `three` и `pixi.js` в корень проекта с редактором: предсборка зависимостей Vite даст две копии three (в редакторе это ограничено `optimizeDeps.entries`).
- **Свои ноды.** `defineNode({ ..., glsl })` для GLSL-бэкендов; для TSL реализация передаётся отдельно: `createEffect(text, { registry, builders: { 'my/node': (inputs, ctx) => ({ ... }) } })`.
- Тест `runtime-isolation.test.ts` следит за границами: ядро (`graph`, `nodes`, `glsl`) не знает ни про рендереры, ни про Vue; каждый рендерер тянет только свою зависимость и не лезет в чужую.

### Один эффект в четырёх бэкендах: проверено

Страница [examples/backends](examples/backends) считает один и тот же файл в TSL (three, WebGPU), GLSL (three, WebGLRenderer), PIXI-фильтре на WebGL (GLSL) и на WebGPU (WGSL), сравнивает кадры по пикселям и умеет мерить скорость. На времени 0, 1,5, 3,7, 7,35 и 10 с (кадр 256x256, шум Перлина, смешивание, френель):

| Пара | Расхождение |
|---|---|
| TSL и GLSL в three | максимум 1/255, среднее 0,000 |
| TSL и PIXI WebGL | максимум 1/255, среднее около 0,05 (PIXI пишет в 8 бит) |
| TSL и PIXI WebGPU (WGSL) | максимум 1/255, среднее около 0,05 |

Шум MaterialX портирован на GLSL построчно из исходников three, поэтому результат побитово близок к TSL. Грубый замер (кадр 1024x1024, 120 кадров, WebGPU в Chrome на этой машине): TSL 0,35 мс, GLSL в three 0,34 мс, PIXI 0,13 мс. Замер не профайлер, и PIXI тут не вполне сопоставим (8-битная цель, другой путь отрисовки), но порядок величин показывает, что TSL и GLSL работают одинаково быстро.

## Частицы

Формат `taofx-particles` (JSON): параметры системы и **граф материала**, который задаёт вид каждой частицы. Один файл работает во всех трёх бэкендах:

```ts
import { createParticles } from '@1337exp/taofx/tsl';        // three + WebGPURenderer
import { createGlslParticles } from '@1337exp/taofx/three';  // three + WebGLRenderer
import { createPixiParticles } from '@1337exp/taofx/pixi';   // PIXI v8 (WebGL), Mesh

const fx = createParticles(text);   // fx.object: Mesh для сцены
scene.add(fx.object);
loop((t) => fx.setTime(t));         // каждый кадр: свой отсчёт времени
```

- **Симуляция на CPU детерминирована, перемотка точна.** Каждая частица считается сама по себе от своего рождения (событие рождения и `seed` задают её свойства, случайные числа это целочисленный хэш: одинаково на любой платформе) фиксированными шагами `step` (по умолчанию 1/60 с). Состояние на момент `t` зависит только от времени и параметров: `setTime` можно вызывать с любым значением, вперёд и назад, результат тот же бит в бит (тесты прогоняют случайные последовательности перемоток против свежего расчёта). Ход вперёд дешёвый (живые частицы дошагивают), прыжок назад пересчитывает живых от рождения: жизнь конечна, поэтому недорого. На шаге ускорение постоянно и движение решается точно (гравитация и сопротивление без накопления ошибки), силы, зависящие от положения, считаются в начале каждого шага.
- **Силы** (`particle.forces`): `turbulence` (curl-шум: бездивергентное поле, частицы вьются, не слипаясь), `attractor` (притяжение или отталкивание, радиус спада), `vortex` (вращение вокруг оси), `wind` (скорость подтягивается к ветру). **Препятствия** (`particle.colliders`): `plane` и `sphere` с отскоком, трением и режимом `kill`. Частицы не знают друг о друге (так перемотка остаётся точной), столкновений между частицами нет.
- **Предел `maxParticles` это кольцо:** когда рождается частица номер `n`, частица `n − maxParticles` исчезает, даже если жива. Правило зависит только от времени, поэтому одинаково при любой перемотке (прежнее «остаются самые молодые среди живых» зависело бы от истории).
- **Расчёт без аллокаций в кадре.** Состояние лежит в типизированных массивах с пулом слотов, случайные числа считаются один раз при рождении. Замер (10 000 живых частиц): 0,6 мс на кадр без сил и 6 мс с turbulence на каждой частице; прыжок назад на 10 000 частиц с turbulence около 0,3 с, на сотни частиц редактора это единицы миллисекунд.
- **Параметры:** `duration`, `loop`, `seed`, `maxParticles`, `step`, `blend` (`normal` или `add`); излучатель: `rate`, `bursts`, форма `point`, `circle`, `cone`, `box`; частица: `lifetime`, `speed`, `size`, `rotation`, `spin` (числа или диапазоны `[мин, макс]`), `gravity`, `drag`, `forces`, `colliders`, `sizeOverLife` (кривая), `colorOverLife` (градиент с альфой); вывод `render`. Пропущенные поля берутся из `defaultSystem()`, значения проверяются строго.
- **Вывод (`render.mode`):** `billboard` (квадрат лицом к камере), `stretch` (квадрат вытянут вдоль скорости на экране: искры, дождь, трассеры; длина = размер · (1 + `stretch` · скорость)), `ribbon` (лента-шлейф за частицей по её недавнему пути: `trail.length`, `trail.segments`, `trail.widthOverLength`). Ленту разворачивает лицом к камере вершинный шейдер (касательная × направление на камеру), поэтому её данные не зависят от камеры и готовы сразу после расчёта; у ленты `uv.x` идёт вдоль пути (1 у головы, 0 у конца), `uv.y` поперёк, ноды `UV → u` и `v` берут эти числа. Лента живёт, пока жива частица: `lifetime` не короче `trail.length`.
- **Сортировка по глубине** (`render.sort`, нужна обычному смешиванию, для `add` не работает и не нужна): поразрядная сортировка без аллокаций, от дальних к ближним, по камере прошлой отрисовки. В PIXI глубины нет: порядок рождения.
- **Вид из графа.** Нода «Частица» отдаёт долю жизни, случайное число, цвет и непрозрачность из градиента; «Radial» даёт расстояние от центра квадрата (круглые и мягкие пятна). В обычном материале и фильтре эти ноды компилятор отвергнет (возможность `particle`).
- **three:** инстансинг для `billboard` и `stretch`, обычный меш для `ribbon`. **PIXI:** динамический `Mesh` (WebGL или WebGPU), преобразования PIXI применяются, ось Y системы вверх, на экране вниз; `scale` задаёт пикселей на единицу.
- **Данные сцены: мягкие частицы и рефракция.** Нода «Затухание по глубине» (`scene/depth-fade`) даёт 0 на поверхности сцены и растёт до 1 на расстоянии `distance` перед ней: умножьте на непрозрачность, и частицы не режутся о геометрию жёстким краем. Нода «Цвет сцены» (`scene/scene-color`) отдаёт цвет уже нарисованного за пикселем со сдвигом: марево, стекло, искажения. У `WebGPURenderer` (TSL) глубина и цвет сцены есть сами. У классического `WebGLRenderer` игра отдаёт текстуры: `createGlslParticles(text, { scene })`, где `scene` это `SceneInputs` (глубина и линейный цвет) или готовый `createSceneCapture(renderer)`, который рисует сцену без эффектов в свой буфер (`capture.render(scene, camera, [fx.object])` перед обычной отрисовкой). Без этих данных компилятор скажет, какой ноде чего не хватает. PIXI (2D) ни глубины, ни цвета позади не даёт.
- **Бюджет и перекрытия.** `measureSystem(system, view)` (ядро, без рендерера и DOM) прогоняет систему по времени и считает пик и среднее число частиц, заполнение в слоях перекрытия (площадь частиц на экране, делённая на площадь экрана: именно заполнение обычно решает производительность), стоимость симуляции и вершины, и замечает упор в `maxParticles`. Годится и для проверки в тестах игры («эффект не больше 4 слоёв»). В редакторе это панель «Бюджет» (честная оценка сверху: без отсечения экраном и глубиной), а кнопка «Перекрытия» включает тепловую карту (`effect.setDebug('overdraw')` в TSL): каждый пиксель частиц считает слои независимо от графа материала, раскраска от синего (1 слой) через зелёный и жёлтый к красному и белому (16 и больше).
- Страница [examples/particles](examples/particles) показывает один файл во всех бэкендах с ползунком времени (`?file=fountain|sparks|trail|smoke|haze|sprites`, `&pixi=webgpu` включает рендерер WebGPU у PIXI); примеры сил, лент и данных сцены генерирует `make-showcase.mjs`.
- **В редакторе:** кнопка «Пример: фонтан» (стартовая система) или «Сделать частицами» в предпросмотре превращает документ в систему частиц. Справа от предпросмотра панель «Параметры» (система, излучатель с формами и всплесками, отрисовка с режимами и шлейфом, диапазоны частицы, гравитация, сопротивление, списки сил и препятствий), редактор кривой размера и градиент цвета с альфой. Кнопка «Окружение» ставит в сцену пол, куб и шар, чтобы видеть мягкие частицы и рефракцию. Внизу полоска таймлайна: пауза, в начало, ползунок-скраббинг с метками всплесков и границ циклов. Правки склеиваются в шаги undo; файл пишется как `taofx-particles`, обычный материал как `taofx`.
  - **Кривая:** сетка с подписями, прилипание к шагу (Shift на время отключает), границы значений (размер не уходит ниже нуля), поля «Время» и «Значение» выбранной точки, «Сбросить» к стандартной кривой. Двойной клик добавляет точку, Alt+клик или Delete убирает; если тащить точку к верхнему или нижнему краю, вид едет следом.
  - **Градиент:** клик по полосе добавляет остановку, Alt+клик убирает, цвет задаётся в sRGB, хранится линейным.
  - Оба виджета (поле графика и полоса градиента) это модули taoux `curveeditor` и `gradienteditor`; поля, переключатели и кнопки вокруг них на TaoUI.

Другие примеры: [examples/plain-three](examples/plain-three): обычная three.js-сцена со светом и полом, эффект как материал меша.

## Ноды

| Категория | Ноды |
|---|---|
| Входные данные | Время, UV (и отдельно `u`, `v`), Радиус от центра, Френель (нужна нормаль), Исходная картинка (PIXI), Частица (только в системе частиц) |
| Константы | Число, Цвет |
| Математика | Сложение, Умножение, Смешивание, Синус, Сглаженная ступень, **Степень** (`pow`), **Ограничение** (`clamp`), **Переназначение** (`remap`) |
| Текстуры и UV | **Текстура** (цвет и альфа по uv), **Спрайт-лист** (кадр по фазе 0…1), **Преобразование UV** (повтор и сдвиг) |
| Шум | Шум Перлина |
| Сцена | **Затухание по глубине**, **Цвет сцены** (нужны данные сцены, см. «Данные сцены»; нет у PIXI) |
| Выход | Поверхность |

Математические ноды работают с типом `gen` (число, vec2, vec3, vec4): скалярные параметры (степень, границы) сами растягиваются на тип входа. Переназначение переносит значение линейно из `[вход от, вход до]` в `[выход от, выход до]` и не обрезает за краями (для этого есть Ограничение); нулевой входной диапазон не даёт деления на ноль. Степень от отрицательного числа не определена (как у самого `pow`), перед ней ставьте Ограничение.

## Текстуры и спрайты

Нода «Текстура» читает картинку по uv: выходы `цвет` (линейный RGB) и `альфа` (прямая, без премультипликации); пока вход `uv` не подключён, берутся координаты самой поверхности (квадрата частицы, меша, спрайта). Начало uv внизу слева во всех бэкендах (PIXI-обёртка сама переворачивает картинку).

- **Спрайт-лист.** Нода «Спрайт-лист» делит картинку на `столбцов × строк` кадров (слева направо, сверху вниз), `фаза` 0…1 пробегает кадры подряд. Подайте в неё «долю жизни» ноды «Частица»: частица проигрывает анимацию за свою жизнь. «Преобразование UV» даёт повтор и сдвиг (подайте время в сдвиг: текстура поедет).
- **Где лежит картинка.** В графе: `textures: { имя: { src } }`, где `src` это URL или `data:`-URI (в редакторе кнопка «Загрузить…» на ноде кладёт картинку в файл как `data:`, до 4 млн символов). Нода хранит только имя в `params.texture`, поэтому одну картинку можно использовать в нескольких нодах. В файл при сохранении попадают только те картинки, на которые кто-то ссылается.
- **Своя текстура из игры.** Любой рантайм принимает `textures: { имя: Texture }` и подставляет её вместо картинки из файла: `createParticles(text, { textures: { smoke: myTexture } })`; для PIXI это `Texture` из pixi.js, для three `Texture` из three.
- **Загрузка.** Картинки из файла грузятся по адресу один раз и кэшируются (`clearTextureCache()` освобождает). Загрузка идёт асинхронно: пока картинка не пришла, текстура пустая, и игровой цикл сам покажет её со следующего кадра. В статичной сцене перерисуйте кадр после загрузки (так делает [examples/particles](examples/particles), `?file=sprites`).
- **Цвет.** three читает картинку как sRGB и отдаёт шейдеру линейный цвет сам; в PIXI шейдер снимает премультипликацию и переводит sRGB в линейный. Ошибка (нет такой текстуры, не выбрана) подсвечивает ноду, граф не падает.

## Как пользоваться редактором

| Действие | Как |
|---|---|
| Двигать холст | колесо мыши или тачпад; правая или средняя кнопка, перетаскивание |
| Масштаб | `Ctrl` + колесо, щипок на тачпаде |
| Добавить ноду | правый клик по пустому месту, поиск в палитре |
| Соединить пины | потянуть от пина к пину (цвет пина это его тип) |
| Создать ноду из связи | отпустить протянутую связь над пустым местом: палитра покажет только подходящие ноды и сама подключит новую |
| Перенести связь | потянуть за занятый вход |
| Значение входа | поле прямо на ноде (число, вектор, цвет), пока вход не подключён |
| Удалить | `Delete`: выбранные ноды или связь |
| Отмена / повтор | `Ctrl+Z` / `Ctrl+Y` |
| Больше места превью | кнопка «Ноды» в шапке превью сворачивает панель нод и возвращает к прежнему размеру; границу между панелями можно тянуть |

Граф сохраняется в браузере автоматически, **Сохранить / Открыть** работают с файлом `taofx.json`. Ошибка в графе (например, нет ноды «Поверхность») показана под предпросмотром, а нода с ошибкой подсвечена; последний рабочий материал остаётся на экране.

## Как устроено

- `src/lib/` — публичные входы пакета (ядро, tsl, three, pixi); ядро это `src/graph/`, `src/nodes/`, `src/glsl/` (без Vue, DOM и рендереров); рендереры: `src/tsl/`, `src/three/`, `src/pixi/`:
  - `types`, `registry`: граф (чистые данные) и определения нод;
  - `resolve`: вывод типов (`gen`-пин получает самый широкий тип среди подключённых, как genType в GLSL), правила связей;
  - `ops`: добавить/удалить ноду, `canConnect` (типы и циклы проверяются пробным выводом типов всего графа), `connect`, подбор пина для палитры;
  - `capabilities`: проверка, что цель даёт нодам нужное (нормаль, картинка);
  - `glsl/`: граф в GLSL (каждая нода считается один раз и кладётся в переменную), шум MaterialX, каркасы шейдеров для three и PIXI;
  - `tsl/`: граф в узлы TSL (`builders.ts` с реализациями нод, время через uniform), материал;
  - `serialize`: строгий разбор файла (недопустимые связи отбрасываются и считаются).
- `src/wgsl/` — то же для WGSL (PIXI на WebGPU): компилятор, каркасы фильтра и частиц, шум MaterialX; GLSL-версия и WGSL-версия делят `walkGraph`, а значит и правила типов и возможностей.
- `src/particles/` — формат и симуляция (`sim.ts`), силы и шум (`noise.ts`), сортировка, ленты и квадраты (`geometry.ts`), общий для three драйвер (`driver.ts`), бюджет (`budget.ts`).
- `src/nodes/<категория>/<имя>.ts` — определения нод (чистые данные: пины, `needs`, GLSL- и WGSL-эмиттеры), подхватываются автоматически. TSL-реализация ноды лежит в `src/tsl/builders.ts`: определения не знают про three.
- `src/editor/` — редактор: интерфейс на [TaoUI](../taoui) (кнопки, поля, переключатели, сплит, подсказки; язык синхронизируется с локалью TaoUI), стор (Pinia, жизненный цикл документа из `taoux/session`), мост к общему холсту `canvasHost`, вид ноды с типизированными пинами и полями значений, слой связей, палитра, панель инструментов.
- `src/preview/` — three.js `WebGPURenderer` и один меш с материалом из графа.
- Типы пинов: `float`, `vec2`, `vec3`, `vec4`, `color`, плюс `gen`. Связь разрешена между одинаковыми размерами и из `float` в любой тип (растяжение); сужение запрещено.

Холст, связи, история, файлы, палитра, измерение пинов, поле редактора кривой и полоса градиента берутся из [@1337exp/taoux](../taoux); интерфейс из `@1337exp/taoui`. Пока taoux не опубликован, он подключён как `file:../taoux`, а TaoUI 3 (слайдеры, `TaoTimeline`) до публикации как `file:../taoui`. Время предпросмотра ведёт `createPlayback` из `@1337exp/taoux/playback` в сторе, таймлайн `TaoTimeline` из TaoUI только показывает его.
